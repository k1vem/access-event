# Подсистема безопасности AccessEvent

## 1. Аутентификация

### Регистрация и вход
- Пользователь передаёт username, email и пароль через HTTPS в production-среде.
- Пароль хешируется функцией Werkzeug generate_password_hash с методом pbkdf2:sha256.
- В базе хранится password_hash, открытый пароль не сохраняется.
- При успешном входе API выдаёт JWT. Срок действия по умолчанию — 24 часа.
- В текущем прототипе refresh-токены и восстановление пароля не реализованы.

### Проверка токена
- Защищённые запросы передают заголовок Authorization: Bearer <token>.
- Сервер проверяет подпись JWT и срок действия.
- Отсутствующий, недействительный или просроченный токен приводит к HTTP 401.

## 2. Хеширование паролей
Используются generate_password_hash(..., method="pbkdf2:sha256") и check_password_hash(...). Пароли не должны попадать в URL, журналы или ответы API.

## 3. Ролевой доступ (RBAC)

| Роль | Права в текущем прототипе |
|---|---|
| guest | Просмотр каталога и деталей мероприятий |
| user | Запись на мероприятия, сообщения, отзывы и свои уведомления |
| organizer | Права пользователя и создание мероприятий; проверка принадлежности при обработке заявок |
| admin | Доступ к маршрутам, разрешённым роли admin |

Администраторская панель и управление пользователями в текущем интерфейсе не реализованы, даже если роль admin предусмотрена для API.

## 4. Рекомендации перед публичным развёртыванием
- Заменить значения по умолчанию для SECRET_KEY и JWT_SECRET на разные случайные секреты.
- Хранить секреты в переменных окружения/секрет-хранилище, не коммитить .env.
- Использовать HTTPS, ограничение частоты запросов, резервное копирование и мониторинг.
- Добавить миграции БД, ротацию токенов и восстановление пароля, если это потребуется.
- Проверить доступность интерфейса с клавиатуры и скринридером.

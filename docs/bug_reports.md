# Журнал дефектов

Записи ниже фиксируют дефекты, выявленные при проверке прототипа, и способ проверки исправления. Перед релизом статусы следует подтверждать повторным ручным прогоном в целевом окружении.

| ID | Дефект | Приоритет | Исправление / проверка | Статус |
|---|---|---|---|---|
| BUG-01 | В каталоге не было понятного пустого состояния | Средний | Проверить отображение сообщения, когда API возвращает пустой список | Исправлено в интерфейсе |
| BUG-02 | Ошибка входа могла раскрывать, существует ли пользователь | Высокий | Для неизвестного email и неверного пароля используется общее сообщение; проверить оба сценария | Исправлено в API |
| BUG-03 | Навигация и формы должны быть доступны с клавиатуры | Высокий | Проверить подписи полей, видимый фокус и ARIA-уведомления | Требует ручной проверки в браузере |
| BUG-04 | Повторная заявка на одно мероприятие могла создать дубликат | Средний | API проверяет существующую запись; уникальность пары user_id/event_id закреплена ограничением БД | Исправлено в API и модели |

## Порядок проверки
1. Запустить `python -m pytest -v`.
2. Проверить формы регистрации и входа в браузере.
3. Проверить запись на мероприятие повторно с одним и тем же пользователем.
4. Зафиксировать дату, окружение и результат повторного теста перед выпуском.
